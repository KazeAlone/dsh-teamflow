# 0.2.5-dev.11 — 任务回归单份描述，通用要求留在模板

仅 dev 开发版本，未发布 npm。更新服务并刷新客户端后生效。

- 普通 `/teamflow` 创建恢复为一次 `create` 提交成员、依赖和完整 `description`。任务不再生成或编辑通用层，不需要第二阶段补全。
- 移除两阶段规划工具、自动续跑补丁、一键双层拆分和双层任务编辑界面。旧工具参数不兼容；调用方应使用 `description`，Workflow 修改仍使用原生 `operations` 对象数组。
- 应用模板时保留模板定义的独立快照，通过 Workflow 讨论结合用户目标细化所有节点。目标明确时直接给出方案；缺少关键信息时先讨论。最终提案只写完整任务描述，保留节点和依赖，由用户统一确认。任务描述必须包含执行所需约束、交付物和验收要求，不依赖执行时拼接模板。
- 只有保存模板时，AI 才从当前任务描述中提炼可复用要求。提炼不修改源任务；模板更新或删除也不修改已有任务。
- 已保存的双层数据读取时合为一份描述，保留未完成配置的阻塞状态；旧的未提交规划草稿保留为待审提案，过期提案仍需重新讨论。此转换仅用于存量数据，不恢复旧工具接口。
- 保留独立 Workflow 讨论、模板库、并行依赖调度、人工验收、重跑及执行记录。main 和 classic 标签不变。

验证覆盖直接创建、旧参数拒绝、模板上下文、完整描述生成、结构保护、缺失信息阻塞、数据转换，以及构建后的 Harness 原生创建、模板提炼/适配、审批执行和冷恢复。确定性模型测试验证流程契约，不代表所有小模型的真实成功率。

106 项相关回归及 Harness 0.2.1-rc.2 打包回归通过。全量检查仍有 6 项既有失败：Windows 符号链接权限 1 项，升级检查器的开发版本识别 5 项。后续 68 项检查已单独通过；依赖 doctor 检查 295 个包身份通过，构建产物与源码一致。
