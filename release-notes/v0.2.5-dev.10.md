# 0.2.5-dev.10 — 创建时自动补全至可运行

仅 dev 开发版本，未发布 npm。更新插件并重启服务、刷新客户端后生效。

- 修复主对话 `/teamflow` 创建仅完成通用层后就提示等待确认的问题。通用层落盘后明确继续第二阶段；部分节点补全后，工具返回剩余任务及其保存的通用要求、原始目标。
- 在 Harness 的回合结束边界检查本次创建。模型提前结束时自动继续补全，最多追加 3 次；完成后停止追加。用户取消、宿主错误、等待用户修改意见、停止团队、独立 Workflow 讨论均不自动重启。普通新对话回合不会重新启动遗留草案，显式查询状态可恢复规划。
- 未完整生成的分层任务显示生成状态，不能确认运行。全部本次任务完成后进入最终审查，用户只需一次确认，不需要逐个节点配置。保留旧版完整描述和完整分层任务的创建方式。
- 仍然使用两次模型工具调用生成两层，避免要求小模型一次输出大型嵌套结构。自动继续不代表能绕过模型或网络故障；失败时保留草案，不伪造任务内容、不自动批准。

验证：真实 ToolRuntime 回归覆盖通用要求与目标回传、提前结束补全、取消、错误、用户反馈和重试上限。固定 Harness 0.2.1-rc.2 的打包测试故意让模型在创建后及部分补全后分别结束回答，检查同一用户请求最终补全全部节点，随后 HTTP 确认运行成功。该确定性测试使用脚本模型，不等同于所有小模型的实际成功率。

同一新增用例对开发版 dev.9 的已打包产物复测，停在缺少本次任务的状态并失败；dev.10 通过。另做了一次账号模型试跑，首个请求后没有记录到文本或工具调用，没有创建团队，测试驱动读取空状态失败；该次不能用来宣称真实模型成功率提升，原因尚未定位。
