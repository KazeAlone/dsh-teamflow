# 0.2.7-dev.1 — Reduce workflow polling and reopening overhead

Development build on `dev`; stable `main` is unchanged.

- Scope status polling to the current captain and skip mailbox reads and artifact audits for unrelated teams.
- Move activity-poll artifact hashing to a single background worker. Identical in-flight audits share work; settled results are not cached, so changed files still invalidate evidence. Worker disposal follows plugin lifetime.
- Keep unchanged activity snapshots referentially stable, avoiding repeated card updates.
- Retain up to four recent workflow views within an 8 MiB serialized-text budget and a five-minute lifetime. Reopening shows the previous view while refreshing; mutations wait for current state.
- Return a small revision acknowledgement when the complete workflow state is unchanged. Live execution changes also invalidate that revision.
- Reuse a host-retained member address instead of refreshing the parent catalog before every navigation on hosts that expose that API.

These fix reproduced overhead in TeamFlow. They do not establish the cause of a particular remote server's startup or history latency without server/request measurements, and do not change Harness's own transcript-loading implementation.
